# BlackWikiSMP 3.3

Paper **26.2 / Java 25**용 통합 약탈 SMP입니다. 3.0 기능을 유지하면서 샷건·저격총·전용 탄환과 총기 내구도를 추가했습니다. Discord 양방향 채팅, 서버 시작·종료·입퇴장 알림과 전원 명령도 유지합니다.


**3.3 추가:** 식량 상점 5페이지, 무덤 열기·회수 복구, Paper Anti-Xray 자동 강화, 5분마다 랜덤 도움말 7종을 추가했습니다. 야생에서는 메인 `/메뉴`를 막고 개별 명령어를 이용합니다. [3.3 사용법](UPDATE_3.3_KO.md)을 먼저 확인하세요. Anti-Xray 프로필을 처음 저장한 뒤에는 전체 재시작이 한 번 더 필요합니다.

## 설치와 이전

1. 서버를 정상 종료합니다.
2. 이전 JAR를 plugins 밖으로 옮기고 **BlackWikiSMP-3.3.jar 한 개만** 넣습니다.
3. 기존 plugins/BlackWikiSMP 폴더와 월드를 유지합니다. config.yml을 지우거나 기본 파일로 덮어쓰지 않습니다.
4. 새 설정만 자동 추가하며 변경 전 설정은 config.yml.before-3.3.bak에 보관합니다.
5. `/업데이트상태`, `/플러그인상태`, `/명령어`, `/디스코드`로 확인합니다.

[Discord 설정·도우미 안내](DISCORD_SETUP_KO.md)를 먼저 읽으세요. **완전히 꺼진 서버를 Discord에서 켜려면 같은 컴퓨터에서 별도 도우미를 상시 실행해야 합니다.** 컴퓨터/호스트 자체도 켜져 있어야 합니다.

기존 베드락·휴대폰 연동, 기본템 1회, 액션바 코인, 40,000×40,000 경계, 10분 무덤, 첫 접속 인사 보상을 유지합니다. 기존 Geyser·Floodgate·ViaVersion·Simple Voice Chat 설치도 유지하세요. 베드락 최초 설치는 [2.8 안내](UPDATE_2.8_KO.md)의 방식이며, 현재 설치 도우미에서는 3.3 JAR를 사용합니다.

## 유지되는 2.2 기능

### 몬스터 레벨과 보상

스폰 보호구역·대기 월드 밖의 적대 몬스터에 **[Lv. 숫자] 이름 ❤ 현재 체력/최대 체력**을 표시합니다. 엔더 드래곤·워든·위더는 레벨·체력 변경·코인 보상 모두 제외합니다. 최대 레벨은 50이며 재접속·청크 재로드 때 다시 뽑거나 체력을 중복해서 올리지 않습니다. 피해·회복 후 체력 표시를 갱신합니다.

| 레벨 | 일반 몬스터 | 강한 몬스터 |
| --- | ---: | ---: |
| 1~25 | 0코인 | 0코인 |
| 26~49 | 10코인 | 30코인 |
| 50 | 35코인 | 75코인 |

강한 몬스터는 **실제 공격력 속성이 6 이상**이거나 `monsters.strong-types` 목록에 있는 종류입니다. 기본 목록은 파괴수·피글린 야수·변명자·소환사·호글린·조글린·엘더 가디언·브리즈·크리킹이며 관리자가 변경할 수 있습니다. 대형 슬라임 등 별도 공격 계산을 쓰는 몬스터를 강한 보상으로 취급하려면 해당 종류를 목록에 넣을 수 있습니다.

생존·모험 플레이어에게 처치가 귀속되어야 코인을 받습니다. 자연 출몰·일반 스포너 등 정상 게임 출몰은 대상이고, 알·명령·외부 플러그인의 CUSTOM 직접 소환 및 크리에이티브 처치는 코인을 주지 않습니다. 2.2를 켤 때 이미 로드된 몬스터도 레벨을 부여합니다. 이전부터 존재한 개체의 과거 소환 경로까지 되짚지는 않습니다.

레벨 가중치는 기본 `0.94^(레벨-1)`로 **한 레벨 올라갈 때마다 낮아집니다**. 50레벨은 약 0.3%로 드물게 나옵니다. 체력은 기본 `원래 최대 체력 × (1 + (레벨-1) × 0.04)`이며, 예를 들어 좀비는 1레벨 20, 50레벨 59.2입니다. 몬스터 공격력은 올리지 않습니다. `/채광 관리` GUI와 `monsters` 설정에서 출현 가중치·체력 배율·활성화를 조정합니다.

### 채광 성장

`/채광`, `/채광레벨`, `/성장`으로 현재 레벨과 경험치 GUI를 엽니다. 생존·모험 상태로 보호구역 밖에서 자연 고체 블록을 캐면 경험치를 받습니다. 기본 일반 블록은 1 XP, 광석은 5 XP, 다이아몬드 광석·심층암 다이아몬드 광석·고대 잔해는 10 XP입니다. 레벨이 한 번 오를 때마다 **30코인**을 주며 여러 레벨을 한 번에 올리면 그만큼 지급합니다.

시작 레벨은 1, 다음 레벨 필요 경험치는 기본 `100 + (현재 레벨-1) × 50`입니다. 채광 최고 레벨은 몬스터의 제한과 별개로 기본 100이며 설정에서 바꿀 수 있습니다. 채광 레벨·경험치는 야생 초기화 후에도 유지합니다.

2.2 이후 플레이어가 설치한 위치, 피스톤·블록 생성 등으로 바뀐 위치, 이미 경험치를 받은 채굴 위치는 다시 보상을 주지 않습니다. 이 이력은 청크에 저장해 재시작 후에도 유지합니다. 설치·파괴 반복이나 광석 재배치로 코인을 복제하지 못하게 하기 위한 처리입니다. 2.2 설치 전의 모든 건축 이력을 자동으로 판별하지는 않습니다. 야생 초기화로 새 차원을 만들면 그 차원의 채굴 이력도 새로 시작합니다.

채광 경험치·레벨 보상·기존 코인은 동일한 플레이어 저장 데이터에 기록합니다. 경험치 곡선을 관리자가 변경하면 표시 레벨도 다시 계산하지만 이미 가진 경험치만으로 레벨 보상을 다시 주지는 않습니다.

### 특별 마검 상점

상점 하단 **이전 / 다음** 버튼으로 이동합니다.

| 페이지 | 상품 |
| --- | --- |
| 1 | 방어구·방패·보호 책 |
| 2 | 검·날카로움 책 |
| 3 | 재료·특별 능력 |
| 4 | 특별 무기 4종·방어구 세트 3종·거인의 혈청 |

`/상점 4`, `/상점 특별`로 바로 들어갈 수 있습니다. 기존 가격을 유지하며 특별 상품을 추가해 총 45개입니다.

| 검 | 기반 | 공격력 | 공격 속도 | 이동 속도 | 내구성 | 가격 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 오리우스의 검 | 다이아몬드 검 | 11.5 | 1.65 | +5% | II | 299,900코인 |
| 악마의 손길이 담긴 검 | 네더라이트 검 | 13 | 1.5 | +6% | III | 799,900코인 |
| 천사의 별 검 | 다이아몬드 검 | 14 | 1.7 | +3% | III | 1,499,900코인 |

이 수치는 기본 플레이어가 **주 손에 들었을 때의 실제 속성**입니다. 보조 손·가방에 두면 증가하지 않습니다. 다른 인챈트·물약·외부 플러그인의 보정은 별도로 적용될 수 있습니다. 공격 속도 1.5도 요청한 숫자 그대로 적용했으며 바닐라 검의 1.6보다 낮은 값입니다.

- **혈투의 기증:** 오리우스의 검으로 적 플레이어를 직접 처치하면 최대 체력 안에서 체력 2칸(4 HP)을 회복하고 신속 I를 3초 부여합니다.
- **코인의 기증:** 악마의 검으로 적 플레이어를 직접 처치하면 상대가 가진 코인의 15%를 소수점 버림으로 빼앗습니다. 새 코인을 만드는 방식이 아니라 상대 지갑에서 차감해 사용자에게 지급합니다.
- **천사의 기증:** 천사의 별 검으로 적 플레이어에게 실제 피해를 주면 상대의 일반 이동·점프를 7틱(정상 TPS에서 0.35초) 막고 사용자에게 저항 II를 2초 줍니다. 재사용 시간은 사용자당 20초이며 재접속해도 타임스탬프를 유지합니다. 사망·관리 이동·접속 종료 시 속박을 정리합니다.

팀원·자기 자신·보호구역·대기열에서는 특수 효과를 사용할 수 없습니다. 처치 효과는 기존 같은 상대 5분 반복 킬 제한을 함께 적용합니다. 마지막 실제 근접 공격이 해당 마검이어야 하므로 처치 순간에 검만 바꿔 들거나 일반 검의 이름을 똑같이 바꿔서 효과를 얻을 수 없습니다. 더 강하거나 오래 남은 신속·저항 효과를 약하게 덮어쓰지 않습니다.

마검의 이름·속성·내구도·인챈트·식별 정보는 보관함·유저상점에서도 보존합니다. `transfers.yml`과 플레이어 처리 기록으로 코인 탈취의 차감/지급 단계를 관리하며 중단된 정산은 해당 플레이어 접속 시 이어갑니다. 백업 중 발생한 탈취는 백업이 끝난 뒤 정산하고, 확인에 필요한 플레이어가 오프라인이면 접속할 때까지 기다립니다. `transfers.yml`과 플레이어 파일은 같은 백업에서 함께 복원하세요.

### 성장 설정 GUI

OP는 `/채광 관리` 또는 관리자 메뉴의 **몬스터 · 채광 설정**에서 활성화·고레벨 출현 가중치·체력 보너스·채광 경험치 곡선·최고 레벨을 조절할 수 있습니다. 세부 몬스터 종류와 경험치 값은 `config.yml`에서도 수정할 수 있고 `/smp reload`로 반영합니다. 백업·야생 초기화 중에는 성장 설정 변경을 잠시 제한합니다.

## 유저상점

1. 판매할 아이템 묶음을 **주 손**에 듭니다.
2. `/유저상점` → **손에 든 아이템 판매**를 누릅니다.
3. GUI의 ±1 / ±10 / ±100 / ±1,000 / ±10,000 버튼으로 가격을 정합니다. `/유저상점 등록 12345`로 가격을 입력하고 GUI에서 확인해도 됩니다.
4. **확인 · 판매 등록**을 누르면 손에 든 묶음 전체를 보관하고 판매 목록에 올립니다. 확인하기 전에는 아이템을 가져가지 않습니다.
5. 다른 플레이어는 상품을 선택하고 구매 확인을 누릅니다. 코인을 차감하고 원래 아이템을 지급합니다.

가격은 **아이템 1개가 아닌 등록한 묶음 전체**의 가격입니다. 등록 수량을 나누려면 손에 들기 전에 나누세요. 이름·인챈트·내구도·설명·커스텀 데이터·상자 내용은 Paper의 아이템 직렬화로 보존합니다. 판매 수수료와 판매 기한은 없습니다. 구매 시 인벤토리 공간·잔액·판매 상태를 다시 검사하며 본인 상품은 구매할 수 없습니다.

판매자는 온라인이면 즉시 코인을 받고, 오프라인이면 다음 접속 또는 `/유저상점 정산`에서 받습니다. 판매 취소는 `/유저상점 내목록`에서 상품 선택 → 확인으로 진행합니다. 취소 아이템을 전부 받을 공간이 없으면 계속 판매 상태로 유지합니다. 상점·유저상점은 스폰 보호구역에서만 이용합니다. 전투·대기·백업 진행 중에는 새 거래와 보관함 이동을 제한합니다.

| 설정 (`market`) | 기본값 |
| --- | --- |
| `max-price` | 묶음당 1~1,000,000,000코인 |
| `max-listings-per-player` | 플레이어당 진행 중 상품 20개 |
| `max-active-listings` | 전체 진행 중 상품 2,000개 |
| `completed-history` | 완료 거래 2,000건 보관, 진행 중 거래는 정리하지 않음 |

유저상점은 `market.yml`의 거래 기록과 플레이어 `.dat`의 처리 기록을 함께 사용합니다. 거래 도중 중단되면 해당 플레이어 접속 시 미완료 등록·구매·반환·정산 상태를 확인합니다. 구매자가 접속해야 완료 여부를 알 수 있는 거래는 그때까지 목록에서 잠깁니다. 저장 오류가 발생하면 유저상점의 새 거래를 중단하고 기록을 보존합니다. 서버를 종료하고 저장 장치 오류를 해결한 뒤 재시작하세요. **market.yml만 지우거나 플레이어 파일만 과거로 되돌리면 안 됩니다. 함께 복원하세요.**

## 코인 상점

스폰에서 `/상점`의 **방어구 / 공격 / 재료·능력 / 특별 장비** 페이지를 선택합니다. 구매·판매는 합계와 수량을 확인한 뒤 실행합니다. 단품은 1·16·64개를 선택할 수 있고 갑옷 세트·능력은 1회씩 구매합니다. 가격표는 아래 값으로 고정되어 있습니다.

갑옷 세트는 머리·상의·하의·신발 **4개**를 함께 인벤토리에 지급합니다. 효과부여책은 모루로 적용하는 실제 인챈트 책입니다. 특별 능력은 아이템을 주지 않고 OP 전용 효과 명령을 콘솔 권한으로 즉시 실행해 **레벨 I**로 적용합니다. 기존 효과가 더 강하거나 더 오래 남아 있으면 차감하지 않습니다. 폭죽은 별이 없는 비행 시간 1 로켓입니다.

이름·인챈트 등이 바뀐 재료는 시스템 상점에 팔지 않습니다. 인벤토리 공간이 부족하거나 잔액이 모자라면 부분 지급·차감 없이 거래를 취소합니다. 각 상품 ID와 정확한 구매·판매 가격은 [SHOP_PRICES_KO.md](SHOP_PRICES_KO.md)에 있습니다.

## 야생 구역 초기화

OP가 `/초기화` → 확인 GUI를 사용하거나 `/초기화 확인`을 실행합니다. `/초기화 상태`로 진행 상태를 확인합니다. 콘솔도 `초기화 확인`으로 실행할 수 있습니다. 실제 OP만 가능하며 `blackwikismp.admin` 권한만으로는 실행할 수 없습니다.

초기화 대상은 설정된 **BlackWikiSMPWild 사용자 차원 한 개**입니다. 현재 야생에 있는 사람을 스폰으로 이동시키고 진행 중인 이동을 취소한 뒤 기존 차원 폴더를 `backups/BlackWikiSMP/wild-resets/`에 옮겨 보관합니다. 새 시드로 야생을 만들고 40,000 × 40,000 경계를 다시 적용합니다. 야생 건축물·상자·드롭 아이템·몹·개인 홈 5개를 초기화합니다. 별도 무덤 아이템 기록은 생성 후 10분 이내라면 유지하며, 소유자가 스폰에서 복구합니다. 초기화가 무덤 만료 시각을 연장하지 않습니다. 스폰·대기 월드·플레이어 인벤토리·코인·보관함·팀·랭킹은 유지합니다. 기존 야생에서 로그아웃한 플레이어는 새 세대에 접속하면 스폰으로 이동합니다.

일반 오버월드·네더·엔드, 스폰과 겹치는 경로, 심볼릭 링크, 관리 대상이 아닌 경로는 안전 검사에서 거절합니다. 백업과 동시에 실행할 수 없습니다. 시작 중 중단된 작업을 발견하면 새 야생 로드 전에 원래 차원으로 복구하고, 안전하게 복구할 수 없으면 원본과 작업 기록을 남긴 채 시작을 중단합니다. 초기화로 보관한 폴더는 자동 삭제하지 않으므로 운영자가 용량을 관리하세요. 새 월드 생성 중에는 서버가 잠시 멈출 수 있습니다.

복구용 야생 폴더를 수동으로 되돌릴 때는 서버를 완전히 종료하고 현재 폴더와 `wild-reset.yml`을 먼저 별도 보관해야 합니다. `wild-reset.yml`의 `source`와 `archive`는 실제 Paper 26.2 차원 경로입니다. 스폰/서버 전체 폴더와 혼동하지 마세요.

## 2초당 1코인

실제 게임에 입장한 동안 2초마다 1코인을 지급하고, 대기열·오프라인 시간은 제외합니다. 남은 1초는 플레이어 데이터에 저장해 재접속 후 이어집니다. 기존 1.9 잔액은 그대로 유지하며 플레이시간 순위는 계속 초 단위로 집계합니다.

## 기존 운영 기능

### Discord 양방향 봇 연동

봇 토큰과 Gateway로 Minecraft ↔ Discord 텍스트 채팅을 중계합니다. OP의 `/디스코드` GUI에서 수신·알림을 조절하고 `/플러그인상태`로 확인합니다. 서버 시작·종료와 실제 플레이어 입퇴장을 알립니다.

[Discord 안내](DISCORD_SETUP_KO.md)에 Message Content Intent, 채널·허용 ID, 도우미 설치와 오류 해결을 정리했습니다. 서버가 완전히 꺼졌을 때 켜려면 도우미를 상시 실행하고 `!서버켜기`를 사용합니다. `!서버끄기`는 일회용 확인 후 정상 저장 종료합니다.

### 인원 설정

```yaml
queue:
  enabled: true
  player-slots: 50
  max-waiting: 30
```

`player-slots`는 실제 게임 인원, `max-waiting`은 추가 대기 인원입니다. 위 예시는 일반 게임 50명과 대기 30명, 접속 정원 80명입니다. OP/대기 우회 권한의 기존 예외는 유지됩니다. `max-waiting: 0`이면 기다릴 수 없습니다. 수정 후 `/smp reload`로 적용합니다. 낮췄다고 이미 들어온 사람을 강제로 내보내지는 않습니다.

관리 GUI와 `/smp slots 숫자`, `/smp waiting 숫자`로도 조정할 수 있습니다. 서버 목록에 보이는 접속 정원은 게임+대기 총합이며 `server.properties` 파일 자체를 덮어쓰지는 않습니다.

### 욕설 검열

`chat-filter.enabled: true`가 기본입니다. `mode: mask`이면 해당 부분만 가리고, `mode: block`이면 메시지 전체를 취소합니다. 일반 채팅과 팀 채팅, 플레이어의 `/msg`, `/tell`, `/w`, `/whisper`, `/me`, `/say`, `/teammsg`, `/tm`, `/r`, `/reply` 메시지 부분에 적용합니다. 외부 플러그인의 알 수 없는 별도 채팅 채널이나 모든 콘솔 출력까지 처리하는 기능은 아닙니다.

`미친`·`존나`는 허용 목록에서 빼거나 금지 목록에 넣어도 코드에서 항상 허용합니다. 같은 메시지의 다른 욕설은 별도로 가립니다. `시발점` 같은 정상 단어는 기본 예외로 넣었습니다. 금지/허용 단어는 설정에서 추가·삭제할 수 있고, 일부 띄어쓰기·기호·제로폭 문자·호환 문자 우회를 정규화해 찾습니다. 모든 변형과 문맥을 이해하는 AI 판별은 아니므로 목록을 운영 방침에 맞게 조정하세요. 검열만으로 자동 차단하지 않습니다.

### OP 차단과 상태

```text
/벤 Steve 0 0 10 0 규칙 위반
/벤 Steve 1 2 30 0 반복 테러
/벤 풀기 Steve
/벤 목록
/플러그인상태
```

첫 예시는 10분, 두 번째는 1일 2시간 30분입니다. 대상 닉네임이 먼저 오고 다음은 일·시간·분·초·사유 순서입니다. 시간은 0~23, 분과 초는 0~59이고 모두 0이면 거절합니다. 기본 최대 기간은 3,650일이며 `moderation.max-ban-days`로 변경할 수 있습니다. 사유는 필수입니다. GUI는 10분·1시간·1일·7일 빠른 선택과 확인 화면을 제공합니다.

이 기능과 상태/디스코드 관리 명령은 실제 OP 플레이어 또는 서버 콘솔/RCON에게만 허용합니다. 일반 유저에게 `blackwikismp.admin`만 주어도 이 명령들을 사용할 수는 없습니다. 커맨드 블록은 허용하지 않습니다.

차단은 UUID 기준으로 `bans.yml`에 먼저 저장한 뒤 적용합니다. 온라인 대상은 접속을 종료하고, 비동기 접속 검사와 로그인 단계에서 차단하며, 재시작 후에도 기간이 유지됩니다. 만료 시 별도 명령 없이 다시 접속할 수 있습니다. 닉네임은 접속 기록이 있는 사람을 사용하고, 미접속 대상은 정확한 UUID를 입력할 수 있습니다. 닉네임 이력이 겹치면 UUID 사용을 요구합니다. `/벤 풀기`는 BlackWikiSMP가 만든 차단만 해제하며 다른 플러그인/바닐라의 별도 차단까지 지우지는 않습니다. 이 플러그인이 비활성화되면 자체 차단 검사도 작동하지 않습니다.

`/플러그인상태`는 버전·가동 시간·게임/대기 인원·접속 정원·TPS·메모리·백업·Discord 전송/실패/대기·필터·활성 차단 수를 보여 줍니다. 봇 토큰이나 인증 정보은 표시하지 않습니다. 자동 백업에는 새 `bans.yml`도 포함합니다.

## 처음 설치 또는 BlackWikiLog에서 이전

1. 서버를 완전히 종료하고 기존 서버 폴더 전체를 별도로 복사해 보관합니다.
2. `plugins`에서 기존 BlackWikiLog / BlackWikiLogBundle / BlackWikiSurvival / BlackWikiQueueTab / BlackWikiPvP의 JAR를 다른 폴더로 옮깁니다. 옛 데이터 폴더와 월드는 남겨 두세요. 기존 플러그인의 추출된 모듈 JAR가 있다면 함께 옮깁니다. 중복 설치가 감지되면 BlackWikiSMP는 기존 데이터를 보호하기 위해 시작을 중단합니다.
3. **BlackWikiSMP-3.3.jar 하나만** `plugins`에 넣고 Paper 26.2를 Java 25로 시작합니다. ZIP이나 소스 폴더는 `plugins`에 넣지 않습니다.
4. OP가 `/메뉴` → 관리자 설정에서 스폰과 슬롯을 설정합니다. 스폰 월드를 바꾸려면 서버를 종료하고 `plugins/BlackWikiSMP/config.yml`의 `worlds.spawn`을 수정한 뒤 재시작하세요. 해당 월드는 이미 서버에 로드되어 있어야 합니다.
5. `/smp antixray apply`를 실행한 후 **서버를 완전히 종료하고 다시 시작**합니다. `/reload` 또는 `/smp reload`로는 Paper Anti-Xray의 실제 전송 설정이 적용되지 않습니다.

처음 설치하면 기존 첫 번째 월드를 스폰 월드로 사용하고, `BlackWikiSMPWild` 약탈 야생 월드와 `BlackWikiSMPQueue` 대기 월드를 생성합니다. 스폰 주위에 종류별 안내 주민 NPC 8명을 배치합니다. NPC를 위해 기존 지형을 깎거나 건물을 덮어쓰지는 않습니다. 스폰 건축물은 운영자가 만들 수 있습니다.

기존 월드·바닐라 인벤토리를 초기화하지 않습니다. **다른 레거시 플러그인의 팀·개인 보호 구역·별도 플레이시간 파일은 자동 변환하지 않습니다.** 원본에 소스와 데이터 파일이 없었으므로 검증되지 않은 방식으로 기존 파일을 읽거나 덮어쓰지 않습니다. 기존 BlackWikiSMP 2.1~2.5의 팀과 랭킹은 보존합니다. 다른 레거시 플러그인에서 처음 이전할 때만 새 데이터로 시작합니다. 약탈 야생에는 개인 땅 보호를 적용하지 않습니다.

## 코인과 보관함

| 단계 | 사용할 공간 | 이번 구매 비용 | 누적 구매 비용 |
| --- | --- | --- | --- |
| 처음 | 1줄 · 9칸 | 무료 | 0코인 |
| 1차 확장 | 3줄 · 27칸 | 5,000코인 | 5,000코인 |
| 전체 해제 | 6줄 · 54칸 | 추가 15,000코인 | 20,000코인 |

게임에 입장한 온라인 플레이어는 실제 경과 2초마다 1코인을 받습니다. 서버 TPS가 낮아 한 번의 갱신이 늦어지면 2초 단위로 반영하며 남은 1초는 저장하고, 대기열·오프라인 시간은 보상하지 않습니다. AFK이더라도 게임 입장 상태면 지급합니다. 코인 랭킹은 누적 획득량이 아닌 현재 잔액 기준이므로 확장 구매 후 순위가 바뀔 수 있습니다. 실제 돈 결제나 직접 코인 송금 명령은 없으며 유저상점 구매 대금은 판매자에게 정산합니다.

`/보관함`의 처음 한 줄만 사용할 수 있고 잠긴 칸을 누르면 확장 GUI가 열립니다. **내 인벤토리의 아이템을 클릭하면 한 스택씩 보관하고, 보관된 아이템을 클릭하면 한 스택씩 꺼냅니다.** 드래그로 옮기거나 숫자키로 아이콘을 가져가는 방식은 사용하지 않습니다. 같은 아이템은 남는 스택에 합칩니다. 보관함이 꽉 차면 들어가는 수량만 보관하고 나머지는 내 인벤토리에 남깁니다. 꺼낼 스택 전체를 받을 공간이 없으면 꺼내지 않습니다. 전투 중·대기 중에는 보관이나 확장 구매를 할 수 없습니다.

저장되는 원본 아이템과 GUI 표시를 분리하며 이름·인챈트·컴포넌트 등은 Paper의 아이템 바이트 직렬화로 보존합니다. 코인·확장 단계·보관 내용은 **일반 인벤토리와 같은 플레이어 `.dat`의 PersistentDataContainer**에 기록합니다. 아이템 이동과 구매 때는 해당 플레이어 데이터를 저장하여 인벤토리와 보관함을 함께 반영합니다. `data.yml`에는 랭킹과 백업용 사본을 두고 재접속할 때 플레이어 파일을 기준으로 불러옵니다. 검사가 실패하면 원본을 덮어쓰지 않고 해당 보관함 이용을 중단합니다.

운영자가 `data.yml`의 코인·보관함 값만 바꾸어 지급하거나 데이터를 복원하면 플레이어 파일과 맞지 않습니다. **월드의 players/data와 BlackWikiSMP 데이터를 함께 보관·복원**하세요. 정상 종료 시 최종 저장하지만, 강제 종료·전원 차단 시 아직 플레이어 파일에 저장되지 않은 접속 보상은 일부 잃을 수 있습니다. 보관함은 개인 금고이며 사망해도 안의 아이템이 일반 인벤토리처럼 드롭되지는 않습니다.

## 스폰 보호 범위

블록 설치·파괴, 상자·주민 등 상호작용, PvP·일반 피해, 폭발·폭발 블록 피해, 불·연소·번짐, 피스톤, 물·용암 흐름, 엔더맨 등 엔티티의 블록 변경, 나무·비료의 보호구역 침범, 액자·보트 등 훼손, 투척·잔류 물약, 포탈 생성·이용을 방어합니다. 외부 폭발의 블록 목록에서도 보호구역을 제외합니다. 스폰 상자는 일반 플레이어에게 열리지 않으며 작업대와 개인 엔더 상자는 사용할 수 있습니다. 스폰에서 직접 버린 아이템은 해당 플레이어를 소유자로 지정합니다.

스폰 건축은 권한과 본인의 `/smp build`가 모두 필요합니다. 이 모드가 모든 엔티티 피해나 폭발까지 해제하지는 않습니다. NPC는 관리 GUI로 삭제하세요. 야생에서는 팀 PvP 설정 외의 개인 땅 보호가 없으며 약탈·TNT가 허용됩니다. 전투 중에는 스폰 보호구역으로 걸어 들어가거나 보호구역으로 진주 이동하는 것도 제한합니다.

## Anti-Xray

`/smp antixray apply`는 `config/paper-world-defaults.yml` 및 로드된 월드의 `paper-world.yml`에서 Anti-Xray 부분을 병합하고, 변경 전 파일을 `.bak`으로 남깁니다. 엔진 3, 높이 320, 갱신 반경 2, 공기 포함 광물 은닉, 권한 우회 꺼짐을 설정합니다. 광물과 지형을 실제로 삭제하지 않습니다. 서버 전체 재시작이 필요합니다.

**완전 차단을 보장하지 않습니다.** Paper도 시드 역산과 범위 확장 같은 우회 가능성을 설명합니다. 이 플러그인은 채굴 패턴만으로 플레이어를 자동 차단하지 않습니다. 실제 X-ray 클라이언트, 시드 역산, 별도 전투 핵 탐지에 대한 침투 시험을 완료했다고 주장하지 않습니다. 운영자는 시드를 공개하지 말고 일반 유저에게 OP·시드 조회 권한을 주지 마세요.

공기까지 은닉하면 노출 광물에 대한 방어가 강화되지만 클라이언트 FPS와 청크 전송 비용이 증가할 수 있습니다. 접속자가 많으면 실제 접속 기기와 서버에서 먼저 확인하세요. Paper 설정을 다른 도구로 다시 변경하면 월드별 덮어쓰기가 생길 수 있으므로 다시 상태를 확인해야 합니다.

공식 설명: [Paper Anti-Xray](https://docs.papermc.io/paper/anti-xray/)

## 백업과 복원

기본 경로는 서버 폴더의 `backups/BlackWikiSMP/`입니다. 월드 디렉터리(26.2의 차원 하위 폴더·players/data·level.dat 포함), 온라인 플레이어 저장 데이터, BlackWikiSMP의 설정·팀·랭킹·NPC·차단·유저상점 거래·야생 초기화·코인 탈취·무덤·이벤트 기록을 보관합니다. 다른 플러그인 폴더와 서버 전체 설정은 이 백업에 포함되지 않습니다.

시작할 때 Paper `World.save(true)`로 저장을 완료하고, 각 월드의 이전 자동 저장 상태를 기억한 뒤 압축하는 동안 자동 저장을 끕니다. 압축하는 동안 코인 상점·유저상점·보관함·무덤 회수를 잠시 멈춥니다. 압축은 별도 스레드에서 처리하고, 성공·실패·정상 플러그인 종료 시 저장 상태를 복구합니다. `.partial` 파일은 완료 백업으로 취급하지 않으며 CRC를 검증한 뒤에만 ZIP으로 공개하고 오래된 완료 백업을 정리합니다. 백업 폴더는 월드 폴더 내부에 둘 수 없습니다. 심볼릭 링크, `session.lock`, 임시 파일은 복사하지 않습니다.

월드 전체 저장 구간과 플레이어 데이터 저장 구간은 서버 주 스레드에서 실행하므로 큰 월드는 이때 잠깐 멈출 수 있습니다. 압축 중 RAM의 플레이는 계속되며 다른 플러그인이 파일을 직접 수정하거나 저장을 강제로 실행하면 동일 시점 보장은 약해집니다. 매우 큰 서버는 별도의 서버 종료 백업·호스팅 스냅샷도 사용하세요. 비정상 강제 종료 도중 남은 `.partial`은 복원에 사용하지 마세요.

복원할 때는 서버를 완전히 종료하고 현재 폴더를 먼저 별도 보관한 뒤 ZIP의 `manifest.txt`에 기록된 경로로 `worlds/`의 각 폴더와 `plugins/BlackWikiSMP/`를 되돌립니다. 원래 절대 경로가 다른 서버에 복원할 때는 실제 새 서버 경로로 직접 매핑해야 합니다. 실행 중 복원하거나 확인 없이 기존 폴더에 덮어쓰지 마세요.

## 기록과 운영 규모

블록 로그는 최근 10,000개 블록 좌표에 대해 메모리에서 최대 8건을 보여 주며, 전체 로그 파일은 기본 16MiB씩 회전하고 과거 5개를 보관합니다. 재시작 전 로그는 `audit*.log`에서 확인합니다. 롤백 기능은 포함하지 않습니다. 읽기 전용 인벤토리는 연 시점의 스냅샷입니다.

랜덤 이동의 비동기 청크 탐색 수를 제한하고, 압축과 데이터 파일 쓰기를 분리했지만 실제 수용 인원은 CPU·RAM·저장장치·시야 거리·다른 플러그인에 따라 달라집니다. 기본 슬롯 50은 설정값이며 50명 이상 동시 접속 성능을 실측한 보증 수치가 아닙니다. 기본 데이터 저장소는 UUID 기반 YAML이며 여러 서버가 공유하는 분산 DB는 아닙니다.

오류를 보고할 때는 Paper 빌드, Java 버전, `plugins/BlackWikiSMP/config.yml`, 재현 명령어와 콘솔의 해당 오류를 함께 전달하세요. 다른 서버로 이전할 때는 `data.yml`, `npcs.yml`, 설정과 월드를 함께 보관하세요.

## 소스 빌드

JDK 25와 Maven 3.9 이상에서 소스 폴더 안에서 실행합니다.

```sh
mvn clean verify
```

결과는 `target/BlackWikiSMP-3.3.jar`입니다. 실제 Paper API `26.2.build.135-stable`을 provided로 참조하며 Bukkit/Paper API 클래스를 결과 JAR에 포함하지 않습니다. 테스트 전용 Probe는 배포 플러그인에 포함되지 않습니다. 검증 범위와 결과는 `TEST_REPORT_KO.md`에서 확인하세요.

## GitHub 릴리스 자동 업데이트

서버가 공개 GitHub 저장소의 최신 릴리스를 30분마다 확인합니다. 새 버전이 있으면 `BlackWikiSMP*.jar`를 `plugins/update/`에 받아 두고, **다음 서버 재시작 때 Paper가 기존 JAR를 새 버전으로 교체**합니다. 실행 중에는 교체하지 않습니다.

1. `plugins/BlackWikiSMP/config.yml`에 저장소를 입력하고 `/smp reload` 또는 재시작합니다.

```yaml
auto-update:
  enabled: true
  repository: 'MOKEA-Studio/BWG'
  check-interval-minutes: 30
```

2. 새 버전 배포: `pom.xml`과 `plugin.yml`의 버전을 올린 뒤 같은 버전의 태그를 올립니다. `.github/workflows/release.yml`이 빌드하고 JAR를 릴리스에 첨부합니다.

```bash
git tag v3.4 && git push origin v3.4
```

- 직접 릴리스를 만들 때는 태그 `v3.4`, 첨부 파일 `BlackWikiSMP-3.4.jar`처럼 맞춥니다. JAR 안의 plugin.yml 이름·버전이 태그와 다르면 받지 않습니다.
- 초안·사전 릴리스(pre-release)는 무시합니다. 태그는 `v3.4`, `3.4.1`처럼 숫자만 씁니다.
- 교체 후에도 파일 이름은 기존 JAR 이름을 유지합니다. 버전은 `/업데이트상태`에서 확인합니다.
- `/업데이트상태`에 확인 결과·받은 버전·오류가 표시되며, 다운로드 완료 시 접속 중인 OP에게 알립니다.
