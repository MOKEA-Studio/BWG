## 실제 서버에서 확인한 내용

- 원본 2.8 JAR로 서버를 시작해 코인, 보관함 에메랄드 7개, 확장 단계, 일반 인벤토리, 홈 5개, 기본템 수령 기록과 스폰 꾸밈을 저장했습니다. 같은 위치의 플러그인 JAR만 2.9로 교체했습니다.
- 코인·아이템·홈·기본템 기록·스폰 수정 블록과 생성 기록이 유지됐습니다. 무덤 만료 기준과 40,000×40,000 경계, 방어구 가격 500/1,500/3,500/15,000도 확인했습니다.
- 두 실제 프로토콜 클라이언트의 입퇴장 알림이 각각 한 번씩 올바른 순서로 나갔습니다. 시작·정상 종료 알림과 중복 이벤트 제거를 확인했습니다.
- Bukkit 채팅/명령 이벤트를 거쳐 Minecraft 메시지가 Discord 전송 대기열로 들어가고 민감한 인수가 숨겨졌습니다. 비동기 Discord 입력이 메인 스레드에서 한글 채팅으로 처리되고 욕설 필터가 적용됐습니다. 중복·봇·다른 서버 메시지를 제외하고, /op 텍스트가 명령으로 실행되지 않으며 되돌아가는 채팅 반복이 없음을 확인했습니다.
- 실제 운영용 컨트롤러에 Discord 모의 전송을 연결했습니다. 허용 계정의 시작 → 실제 Paper 준비 → 접속·데이터 확인 → 일회용 번호 확인 → API 정상 저장 종료 → 게임 프로세스가 꺼져도 Gateway 유지 → 다시 시작 흐름을 두 차례 수행했습니다. 허용되지 않은 요청도 거부했습니다.
- 도우미 모드에서는 플러그인이 두 번째 Gateway나 중복 서버 알림을 만들지 않았습니다. 플러그인 상태에서 인증된 도우미 접속을 확인했습니다.
- 실행 중 월드의 도우미 최초 설정은 거부되고 설정 파일이 유지됐습니다. 종료 뒤 실제 실행 도우미로 설정이 성공하며 사용자 지정 실행 인수와 인증 키도 유지됐습니다.

## 검증 범위와 배포 일치

개인 봇 토큰이 제공되지 않아 실제 Discord 계정/서버에 메시지를 보내지는 않았습니다. Discord HTTP/WebSocket은 로컬 모의 서버 또는 모의 전송기를 사용했습니다. 게임 서버·클라이언트·인증 API·프로세스 저장 종료와 데이터는 실제입니다. 배포 후 봇 토큰, Message Content Intent, 채널 권한을 본인의 Discord에서 확인해야 합니다.

선택 연동인 Geyser/Floodgate/ViaVersion과 음성 플러그인을 제거하지 않습니다. 이번 실제 서버 검사는 이 선택 플러그인이 없는 상태의 SMP 동작을 포함합니다. 새로운 휴대폰 로그인이나 공유기 외부 접속 검사는 하지 않았습니다. 이전 2.8의 브리지 검사 자료는 verification/previous-2.8에 있습니다.

검사용 Probe/Harness의 일부 이벤트·클릭·Discord 입력은 API와 리플렉션으로 주입했습니다. 이 검사용 클래스는 배포 JAR에 포함하지 않습니다. 테스트에서 한 번에 실행한 게임 JVM은 한 개이며 사용한 테스트 계정과 토큰은 모의 값입니다.

기존 클래스 112개 중 101개의 바이트가 원본 2.8과 동일합니다. 변경은 Discord 기능과 연결 GUI/명령·설정 이전·상태·백업 등의 연결부입니다. 실제 서버에 올린 JAR와 배포 JAR의 SHA-256도 동일합니다.
